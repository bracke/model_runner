Each fixture needs exact input token IDs or input text and tokenizer identity,

Capture independently before exercising the corresponding native operation:

| Fixture | Required observations |
| --- | --- |

| Depth attention | Candidate states, normalized values, query scores, probabilities and mixed outputs |

| Convolution | Static taps, dynamic taps, lag ordering, before/after history and scaled output |
| MoE | F32 logits, correction bias, selected IDs, unbiased weights and expert aggregation |
| Complete decoder | Embedding, all visits, final depth mix/norm and unpadded logits |
| Session lifecycle | Prefill/decode, reset/reuse, rewind/alternative continuation and cancellation recovery |

Test first-pass absence of messages, passes two/three, zero and signed gates,
non-finite handling, local-window/relative-extent boundaries and positions

tolerances must be measured by precision/backend and recorded with error
distributions; none is specified yet. Router ties require an explicit policy.
Plausible text or agreement on a few tokens is insufficient for logits or
intermediate-state qualification.

Build the existing upstream targets `llama-tokenize`, `llama-completion`,
`llama-bench`, `llama-perplexity` and `llama-eval-callback`. The completion
target is available without the server; `llama-cli` is gated with the server

For activation capture, apply `tests/fixtures/inkling2/reference-capture.patch`
to that exact source using `patch -p1`, then rebuild `llama-eval-callback`.
The patch's SHA-256 is
`2e97e9a28cb74168ad34e8894e4beb741bde8ccfd2e629cb575c0528a4b20462`.
It adds callback names for loop messages/controller outputs and filters the
existing callback to attention, feed-forward, routing and output boundaries. It does
not change model equations. The directory named by `INKLING_FIXTURE_DIR`
must already exist. A capture invocation, after full payload verification, is:

```text

  -m /absolute/path/Inkling-2-Mini-Q4_K_M.gguf -p Hello \
  -c 32 -b 8 -ub 8 -ngl 0 -ctk f32 -ctv f32 -fa off -t 7
```

This command was executed against the verified file, with `--no-repack` added.
It is a diagnostic capture, not a throughput benchmark. Each selected
tensor has a `.shape` file containing `f32-le ne0 ne1 ne2 ne3` and a `.f32`
file of all values, dimension zero fastest. Selected-expert IDs instead use
`i32-le` and `.i32`. The exporter follows actual tensor strides and rejects
non-finite floating-point values. This host is little-endian; the raw
exporter's format must be checked before using it on another host. Hash every
capture, retaining command, logs and compiler identity. Callback suffixes are
runtime state IDs, not monotonically ordered execution positions; use the
independent schedule trace to resolve later visits.

Set `INKLING_STEPWISE=1` to process the same prompt one token at a time,
using upstream `common_batch_get_one` to append at the next cache position.
The normal invocation processes the prompt as a batch. Use separate output
directories: incremental callbacks overwrite a tensor's files after every
token, so those files retain the final token's state. Prefill tensors may
retain all token columns; select the final column for that comparison.
Include `--no-repack` when recording the initial unmodified-layout fixtures.

Both capture modes were exercised on the existing TinyLlama Q8_0 checkpoint
with `The capital of France is` (six tokens including its BOS), exact F32
KV, seven CPU threads, no repacking and flash attention off. All 32000 final
logits matched exactly, with greedy ID 3681. This checks the capture mode's
position handling on TinyLlama, not Inkling's loop or convolution state.

The exporter was exercised with the existing TinyLlama Q8_0 checkpoint:
156 F32 tensors were captured, including 32000 output logits. With flash
attention explicitly off, the first three logits agreed with the existing
independent TinyLlama recording within its established 0.08 tolerance
(maximum observed difference 0.024). Flash-attention auto produced a larger
0.095 difference on that check; no tolerance was widened. Initial CPU captures
therefore specify `-fa off`. This exporter check does not qualify Inkling or
establish its numerical tolerances. Restore the unmodified source before

## Native replay and current operating profile

The supported activation profile for this checkpoint is F32. Its weights remain
in the original Q4_K_M GGUF encoding. Integer activation execution has not passed
the canonical checkpoint suite and is not a qualified substitute for this profile.
The fixed model always executes three core visits, including when `--no-think`
requests the official template's `none` reasoning setting.

For the 32 GB Ryzen 7840U system, the current acceptance task uses mapped CPU
weights, eight threads, F32 cache, no repacking, an explicit 24 GiB allocation
limit and a bounded context. For example, from the repository root:

```sh
./bin/model_runner run /models/Inkling-2-Mini-Q4_K_M.gguf --backend cpu --threads 8 --arith f32 --kv-cache f32 --repack none --memory-limit 24G --context-size 4096 --no-think --max-tokens 256 --no-cache --prompt 'Write a short Ada function that adds two integers.'
```

Vulkan and the existing hybrid/host-sharing layouts have numerical conformance
results. This does not establish a useful throughput profile on the 780M. A
shared-weight CLI diagnostic was cancelled after approximately 164 seconds of
prefill for five tokens, so the real workflow retry uses CPU. That diagnostic
was not a repeatable performance campaign. The CPU panel layout also passes all
834 observations and the 16-token greedy fixture, but the F32 fallback extracts
rows from panels; no speed advantage is claimed for it.

The optional full-checkpoint AUnit test replays a selected precision manifest.
From `tests/`, set `MODEL_RUNNER_INKLING_MODEL` to the verified file,
`MODEL_RUNNER_INKLING_REFERENCE` to `fixtures/inkling2/q4_k_m-f32-prefix`, and
`MODEL_RUNNER_INKLING_ARITH=f32`, then run:

```sh
./bin/tests test --only 'native Inkling : optional'
```

`MODEL_RUNNER_INKLING_BACKEND=hybrid` selects the existing mapped-weight path with
an explicit 4 GiB device budget; `device` selects host sharing and its explicit
24 GiB host allocation bound. `MODEL_RUNNER_INKLING_REPACK=rows` separately
qualifies the existing CPU panel representation with the same host bound.
For F16 stored cache, use `MODEL_RUNNER_INKLING_CACHE=f16` with
`fixtures/inkling2/q4_k_m-f32-half-prefix`; its independent precision envelope
must not be substituted for the F32-cache tolerance.

The current no-adapter regression measurement is in
[the Inkling evidence](inkling2-no-adapter-evidence.json). It preserves the prior
Qwen fixed-work CPU claim after shared engine changes; it is not an Inkling
throughput or autonomous-task-quality benchmark.
